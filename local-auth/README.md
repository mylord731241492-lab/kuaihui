# 聚禾客服平台：本地账号与授权试运行

## 当前源码与版本

本目录是 r9 账号与授权服务源码；r9 服务和 `3.8.4-juhe.3` 客户端于 2026-09-26 完成过线上发布。当前客户端源码及本地候选为 `3.8.4-juhe.6`，本次代码提交不重新部署账号服务，也不发布 `.6` 更新清单。客户端候选范围见 [构建说明](../BUILD.md)。

新版包含管理员账号与8小时会话、手机号注册、短信验证修改/找回密码、手机号验证绑定与换绑，以及手动检查更新。用户密码统一使用绑定手机短信验证，不再提供恢复码或客服重置码。正式后台不再接受浏览器输入长期管理密钥。店铺数量不限；套餐控制同时登录的电脑台数，允许额度内多台电脑同时在线，不再由新电脑登录挤掉旧电脑。

首次管理员初始化：在本目录设置 `JUHE_DATA_DIR` 指向实际数据库目录，然后执行 `node admin-cli.mjs init admin`。在该目录 `administrator-initial-password.txt` 查看一次性生成的初始密码，登录后台后修改密码；将凭据保存到密码管理器后删除此文件。只有掌握服务器文件权限的人才能执行 `node admin-cli.mjs reset admin` 重置管理员。不要把初始密码文件打入部署包。

生产部署说明见 [部署说明](../deployment/README.md)，账号、电脑额度迁移和短信配置详见 [账号指南](account-security-guide.md)。手机号是唯一注册方式；短信不可用时无法注册或通过短信改密，没有跳过验证的注册入口。自动支付尚未接入；`.6` 的知识库、商品学习和模型连接在客户端本地实现，详见 [AI 使用与实现说明](../docs/ai-runtime.md)，账号服务本身不承载这些 AI 数据和模型请求。

2026-09-25 增加 Spug 平台验证码通道，用于手机绑定/换绑与找回密码，后续接入手机号注册。新部署选择 `JUHE_SMS_PROVIDER=spug`，仅服务端配置 `JUHE_SPUG_TEMPLATE_CODE`；旧环境未指定服务商仍沿用原 Aliyun。香港无自有域名的部署入口见 [IP 部署说明](../deployment/README-IP.md)。仓库自动测试使用模拟通道，不发送真实短信；历史 r9 发布验收另包含实际短信注册。

在本目录运行 `npm test` 可执行隔离服务测试。当前管理员初始化与配置以上文及账号指南为准。

**以下各节为历史 3.7.1 和独立演示记录，包括旧管理密钥、账号注册和单电脑会话流程；不作为当前源码的启动或操作指南。**

## 3.7.1 客户端接入（2026-09-24）

原客户端现已接入本服务：`../release-3.7.1/win-unpacked/聚禾客服平台.exe`。默认连接 Docker 的 `http://127.0.0.1:47832`，先运行下方 Docker 启动命令，再启动客户端。客户界面没有管理员入口。

登录与注册是独立视图，通过“注册新账号 / 返回登录”切换。3.7.1 支持一账号绑定多台电脑，同时只保留一个有效登录会话。新电脑登录如发现其他设备在线，会询问是否接替；确认后服务器立即撤销旧会话，在线旧客户端在下一次请求或最多约15秒心跳时返回登录。没有联网的旧窗口无法即时收到通知，恢复联网后会验证失效。

账号页“设备管理”可查看绑定记录并自行解绑；解绑当前电脑会退出登录。工作台右上方“账号与设备”可返回管理入口。解绑保留套餐和店铺数据，之后该设备仍可用正确密码重新登录绑定。升级自动导入旧版绑定记录，管理员“解绑设备”清除全部绑定并撤销全部会话。设备绑定依靠 Windows 保护的本机密钥，不是防克隆或硬件防破解保证。

已接入注册、密码登录、授权码兑换、进入原工作台、设备解绑后退出工作台、店铺增删改查及套餐数量限制。启动后需要重新登录；真实授权令牌与设备私钥不传入网页。账号与授权数据保存在 Docker 命名卷中。

管理后台地址为 `http://127.0.0.1:47832/admin`，本机管理员密钥在 `data/docker-admin-key.txt`。生成授权码后在客户端兑换。服务地址可通过环境变量 `JUHE_SERVICE_URL` 或客户端用户目录下的 `juhe-service.json`（`{"url":"https://你的服务域名"}`）配置；远程服务必须另行部署并配置允许的域名，目前仅完成本地联调。

尚未接入短信验证码、找回密码、自动支付或定制 AI；未支持的旧后台接口会明确提示尚未接入，不会假装保存成功。未验收真实电商平台账号和消息收发。新版本仍使用原“快回”数据目录兼容已有数据，本轮自动验收使用独立目录，不覆盖真实店铺数据。

下方“独立试运行版”描述保留用于运行旧的独立演示，不代表 3.7.1 客户端的最新接入状态。旧的独立桌面演示没有多设备管理和接替确认界面，请使用新版实际客户端。

## 历史独立试运行版

这是独立的本地桌面试运行版，不替换已构建客户端，不读取原客户端店铺、Cookie、账号数据，也没有连接旧后台或接入真实支付。当前实现为 Node.js 24 原生 JavaScript + SQLite，桌面运行使用仓库 Electron 34。仅监听 `127.0.0.1:47831`。

## 启动

双击本目录 `启动本地试运行.cmd`（依赖本机已安装的PowerShell 7和Node.js 24）。也可用PowerShell 7执行 `start-trial.ps1`。它启动本地服务并打开桌面试运行窗口。在窗口右上角选择“本地管理”即可生成授权码和管理试运行账号。也可浏览器打开 `http://127.0.0.1:47831/admin`，输入本目录 `data/admin-key.txt` 中的本地管理密钥。

桌面程序已构建在 `../release-auth/win-unpacked`，与原客户端分开。重建命令（在kuaihui目录）：`node node_modules/electron-builder/cli.js --config local-auth/electron-builder.json --win --x64 --dir --publish never`。

1. 注册：3～40位字母、数字或下划线，密码10～128字符，无短信费用。注册后再登录。
2. 登录：首次成功登录绑定当前设备。密码错误不绑定。待激活或到期账号可以登录兑换页面。
3. 生成授权码：本地管理后台选择月卡／年卡、店铺数量。完整授权码仅生成时显示，30天内兑换。
4. 激活：客户端输入授权码，一次性兑换；从兑换日按日历月份计时，月底截到目标月最后一天。
5. 续费：有效套餐从原到期时间续接。到期后从兑换时间起算。有效期内不同店铺数暂不允许自助切换。
6. 换机：管理员“解绑设备”撤销该账号全部旧会话；下一次登录绑定新电脑。账号停用和未兑换码作废也可在后台操作。

## 数据与边界

- `data/accounts.sqlite` 为真实持久化数据库，WAL模式；密码使用带独立盐的scrypt，授权码和会话令牌仅存哈希。备份时使用 SQLite 一致性备份或停服务后复制完整数据库，不能在线只复制主文件。
- 桌面使用Ed25519密钥、Windows safeStorage保护私钥，不以IP或浏览器标识代替机器绑定。挑战限时且一次性；会话请求签名包括路径、方法、时间、随机数及正文摘要，服务器防重放。
- 会话12小时；重开客户端需要登录。客户端15秒刷新一次授权，连接失败显示“授权未验证”，没有离线成功兜底。
- `data/desktop` 与原“快回”用户目录隔离。本地文件不要提交到Git，不要公开管理员密钥。
- 本地管理入口自动读取本机管理员密钥，只适用于开发试运行，正式客户包必须移除此能力。
- 当前界面验证套餐状态和店铺上限数值，**尚未将原客户端的店铺新增、业务功能和授权校验接入此服务**，没有声称已对原客户端实施收费限制。
- 不含找回密码、生产管理员多因素认证、线上HTTPS部署、自动付款或AI服务；不能直接对公网开放。
- 测试：`npm test`，使用独立临时SQLite库，不修改试运行账号。

停止服务可关闭对应Node进程；关闭桌面窗口不会删除账号数据。原安装包与本试运行版独立。

## Docker本地调试

在本目录执行：

```powershell
docker compose up -d --build
docker compose exec -T auth npm test
node docker-smoke.mjs
docker compose ps
```

后台：`http://127.0.0.1:47832/admin`。本轮调试管理密钥已导出到`data/docker-admin-key.txt`，不要提交或公开；容器内原文件为`/data/admin-key.txt`。如需重新取出，运行`docker compose exec -T auth cat /data/admin-key.txt`。

- 容器使用独立命名卷`juhe-auth-debug_auth-data`，没有挂载Windows原试运行账号库。
- 原桌面试运行仍连接47831，**当前并未自动切换到Docker的47832**。本轮Docker验证使用真实HTTP和模拟设备密钥，不等同于Windows客户端已经完成容器服务联调。
- 镜像仅包含服务、页面、Logo与测试；不包含本地data、密钥、客户端用户数据或其他项目文件。
- 非root运行，文件系统只读，数据卷可写，CPU上限1核、内存512MiB，端口仅绑定127.0.0.1。容器内绑定0.0.0.0仅用于Docker端口转发。
- Compose默认使用本次已验证的Node镜像摘要（容器Node v24.21.0），因本机Docker Hub认证连接失败而从公共ECR镜像源获取。可通过`JUHE_NODE_IMAGE`覆盖。
- 本机默认网段池已用满，因此配置独立`10.254.220.0/24`，已检查与本机现有Docker网络不重叠；其他机器冲突时用`JUHE_DOCKER_SUBNET`调整。
- `docker-smoke.mjs`会创建并最终停用自己的测试账号，执行该Compose项目服务的重启、强制终止和重建，以及SQLite快照检查。仅用于调试项目，不在生产服务执行。
- `docker compose stop`停止服务，`docker compose down`移除本项目容器/网络但保留卷。不要使用`down -v`，否则会删除调试账号数据。
