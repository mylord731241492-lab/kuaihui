# 当前源码：账号安全配置与边界

本指南描述当前账号服务源码。客户端 `3.8.4-juhe.3` 与账号服务 r9 曾于 2026-09-26 完成发布；当前客户端源码为 `3.8.4-juhe.6` 本地候选。提交代码不会自动部署服务，线上实际版本需在发布时另行核对。

## 管理员

数据库自动增加 administrators、admin_sessions、security_audit 等表，旧用户、授权和设备记录保留。初始化/本机紧急重置命令为 `node admin-cli.mjs init admin` / `node admin-cli.mjs reset admin`，数据库位置由 `JUHE_DATA_DIR` 指定。初始随机密码写入该目录 `administrator-initial-password.txt`，不打印到日志；保存后删除该文件。

后台 `/admin` 使用用户名密码登录，密码为 scrypt 慢哈希。会话8小时，HttpOnly/SameSite=Strict cookie；HTTPS部署增加Secure；管理写请求须附 `X-Juhe-Admin: 1` 并通过来源校验。退出/管理员改密/本机管理员重置撤销对应管理会话。管理审计可查询、翻阅更早记录，不记录密码或短信验证码。

长期管理密钥浏览器登录已关闭。`JUHE_ALLOW_LEGACY_ADMIN_KEY=1` 仅为明确本地迁移兼容；设置公开服务地址时禁止开启。不要在生产开放旧密钥认证。

## 用户管理（后台修订 r3）

后台登录后默认进入“用户管理”，授权码、审计和管理员设置有独立入口。用户列表支持按账号子串或数字ID搜索、状态筛选及服务器分页；顶部统计为全体用户数量，不随搜索条件改变。状态互斥：已停用优先，其余根据套餐分为有效、待激活、已到期。

用户详情展示注册时间、最近成功登录、同时登录电脑额度、在线数量和绑定设备。在线状态要求账号未停用、设备仍绑定、会话未到期且90秒内有通过验证的请求；这是服务端心跳判定，并非操作系统实时连接状态。已绑定但离线的电脑不占登录名额。后台没有“当前电脑”的用户会话视角，不再突出某一台为唯一有效设备。保留解绑全部设备、停用/恢复账号的操作；用户密码统一通过绑定手机短信验证修改，后台不再生成密码重置码。

管理员只读接口：`GET /v1/admin/users?q=&status=all&page=1&pageSize=20`（每页1～100，搜索最多40字符），以及 `GET /v1/admin/users/:id`。使用现有管理员Cookie和来源校验；列表与详情不返回密码哈希、盐、设备公钥、会话令牌或完整手机号。旧 `/v1/admin/state` 保持兼容，新后台通过 `?includeUsers=0` 只获取授权码记录，避免额外加载全量用户。

## 自定义授权码（后台修订 r4）

“授权码”页面支持随机批量生成1～100个，或自填8～64位英文字母、数字、下划线、连字符的单个码。自定义码去除首尾空白并统一大写，同一内容不可重复创建，已兑换或作废后也不可复用。完整码仅在生成结果中显示，可复制全部或下载TXT；切换栏目保留当前结果，刷新页面或退出后清除。数据库仍仅保存哈希和尾号。

月卡、年卡保持原日历月算法；新增1～3650天自定义时长，每天按24小时计算。套餐按兑换时点或仍有效的原套餐到期时间续期；有效套餐续费须保持相同电脑额度，变更额度需联系客服。所有码仍须生成后30天内兑换，一码一次使用。批量创建在单个事务中执行，失败全部回滚。旧数据库自动新增可空的 `codes.days` 字段，旧月卡年卡不变。

`POST /v1/admin/codes` 接受 `mode: random|custom`、`count`、`deviceLimit: 1..999`，以及 `months: 1|12` 或 `days: 1..3650` 二选一。自定义模式须 `count: 1` 和 `customCode`。响应含 `codes: [{id,code}]` 与 `count`，单个结果继续兼容原 `id,code`。旧请求的 `shops` 字段仅作为电脑额度的兼容别名；同时传入时须与 `deviceLimit` 一致，不再限制店铺。创建自定义天数授权码后，不应直接回退到不认识 `days` 的旧服务程序。

## 同时登录电脑与店铺

- 店铺不限量，添加店铺仍须套餐有效并符合原有归属、重复校验。授权信息返回 `shopUnlimited: true`、`shopLimit: null` 和 `deviceLimit`。
- 电脑以各自设备密钥区分。额度内登录会保留其他电脑的有效会话；同一电脑重新登录仅替换本机旧会话。达到额度后拒绝新增登录，返回409、`code: DEVICE_LIMIT`及`deviceLimit`，没有强制接替入口。
- 会话最长12小时。客户端每15秒发送验证请求；服务端按最近90秒内通过验证的请求计算在线设备数，绑定的离线设备不占用额度。登录、失联后恢复请求均在事务内检查名额；恢复时名额已满会要求该电脑重新登录，不能挤占其他电脑。
- 退出、关闭应用或解绑单台设备只撤销该设备会话；退出请求失败或突然断线时，约90秒后释放在线名额。改密、找回密码、管理员停用或解绑全部设备仍撤销全部登录。
- 旧库首次升级增加 `users.device_limit`、`codes.device_limit`，把有效的原 `shops` 数量迁移为电脑额度，原列保留供兼容。无有效数量的账号默认1台，供未激活用户登录兑换。迁移只执行一次，不会在重启时用旧列覆盖新额度；同时增加会话 `last_seen` 字段和索引。
- 服务器、管理页与客户端须配套发布。旧版客户端不认识新增电脑额度；回退服务程序也会恢复旧的单电脑/店铺数量逻辑，不能把旧包回退当作同规则运行。

## 用户密码和手机

- 工作台的账号、到期状态区域统一为“用户状态”入口；套餐与激活、设备管理、账号安全、短信改密、手机绑定及退出登录都在其中，不再额外显示“账号与设备”按钮。可鼠标点击或通过 Enter / 空格打开。
- 登录使用全屏主窗口。有效套餐登录后直接进入工作台；未激活或已到期账号打开独立的用户状态窗口以兑换授权码。“用户状态”为不全屏的独立小窗，重复打开会聚焦已有窗口；关闭或返回工作台仅收起小窗，不退出账号、不重新加载工作台。退出登录、解绑当前设备、改密成功或登录失效会关闭小窗并返回主窗口的全屏登录页。
- 手机号验证是唯一注册方式：手机号、短信验证码、密码和确认密码。通过验证码后才创建账号，账号名为注册手机号，同时完成手机绑定；使用该账号名和密码登录。桌面不再提供账号注册选项，旧账号、授权与设备记录保留，已有账号仍可登录。
- 手机注册不会合并或覆盖已有账号；手机号已作为账号名或已绑定其他账号时拒绝注册。旧 `POST /v1/register` 接口始终返回410并提示升级客户端使用手机号注册，没有配置开关或测试旁路；旧试运行页面及IPC也不再提供账号注册。换绑更改安全手机号，账号名不变。
- 登录后修改密码需已登录设备签名与绑定手机收到的短信验证码，不再要求原密码。`POST /v1/phone/send` 的 `purpose: change` 由服务器选取当前绑定手机号，`POST /v1/password/change` 接收 `challengeId`、`code` 和 `newPassword`。验证码只用于本次改密，不能用注册、绑定或找回验证码替代。
- 忘记密码时只填写已绑定手机号、短信验证码、新密码与确认密码。`POST /v1/phone/send` 的 `purpose: reset` 接收 `phone`；`POST /v1/phone/reset` 接收 `phone`、`challengeId`、`code` 和 `newPassword`。成功后返回原账号名供登录页预填，换绑不改变原账号名。
- 改密和找回成功均撤销所有旧登录及未使用的短信验证码，设备记录与套餐保留。用户恢复码、客服重置码入口已移除；旧 `/v1/password/recovery-code`、`/v1/password/reset`、`/v1/admin/reset-code` 均已关闭并返回410，历史表只为数据兼容保留。
- 手机绑定/换绑需要当前登录、密码和新手机收到的验证码；同手机号只能归属一个账号。短信找回只匹配该账号已经验证的手机号。
- 验证码6位，Spug固定十分钟模板对应10分钟内一次有效；原有其他短信适配仍为5分钟。最多5次猜错；按手机号、账号、客户IP和全局预算限流。失败/超时不会当作验证成功，无自动重复发送。
- 公开手机找回的发送回复保持一致，未匹配账号时不发送短信。密码和短信验证码不写日志。尚未绑定手机的旧账号需先用原密码登录并绑定手机；短信暂不可用时不会绕过验证。

## 短信服务选择

后台“管理设置 → 短信认证（Spug）”可选择沿用环境配置、使用Spug或关闭短信，保存需再次输入当前管理员密码。初次启用Spug须填写模板Code和每日发送上限（1～5000）；以后Code留空保留原模板。保存立即生效，不发送测试短信、不重启服务。关闭短信保留模板，之后可以再次启用。配置不完整或损坏时不发送短信，不自动切换通道。

管理接口 `GET /v1/admin/sms` 仅返回状态与脱敏模板尾号；`POST /v1/admin/sms` 接受 `mode: environment|spug|disabled`、可选 `templateCode`、Spug模式的 `dailyLimit` 及 `adminPassword`，采用现有管理员会话、来源校验与限流。保存配置使未完成的验证码失效，已使用的当日发送额度不清零；配置变更期间尚在发送的验证码也不能重新变为可用。

环境模式仅服务端设置 `JUHE_SMS_PROVIDER=spug` 或 `aliyun`。新部署配置默认选择 `spug`；旧环境未设置该变量时仍沿用 Aliyun，避免旧服务升级后意外切换。无法识别的名称或所选服务商配置不完整时，短信不可用，不自动改走另一通道。

客户端通过 `/v1/security/status` 获取短信是否已经配置；这不代表实名、额度、白名单和运营商送达已经验证。短信用于手机注册、绑定/换绑与找回密码，登录使用账号（手机注册时为手机号）和密码。`JUHE_SMS_DAILY_LIMIT` 是全服务每日发送尝试上限，默认100；失败和超时也计入，避免反复调用产生费用。

## 手机注册接口（3.8.3 / 服务端 r8）

`POST /v1/phone/register/send` 接收 `{ "phone": "13800000000" }`，返回 `{ "challengeId": "...", "message": "验证码已提交发送，10分钟内有效" }`。业务验证码为6位数字。发送失败、配置变更或等待发送时过期的验证码不可使用。

`POST /v1/phone/register` 接收 `{ "phone": "13800000000", "challengeId": "上一步返回值", "code": "短信中的验证码", "password": "10至128字符密码" }`。成功返回 `{ "username": "13800000000", "message": "手机注册成功，手机号已验证绑定，请使用手机号和密码登录" }`；不自动授予套餐或签发登录会话。客户端继续使用现有设备挑战及签名登录流程。示例用于接口说明，不是发送测试。

升级自动新增 `phone_registration_otps` 表，注册前不创建用户。验证码按手机号和挑战绑定，只保存HMAC摘要；注册、绑定和找回之间不能互用。注册事务内再次校验有效期、尝试次数、短信配置版本、手机号归属，并原子创建账号、绑定手机号和消费验证码，防止并发重复使用。全部用途共享手机号一分钟一次、每天10次、IP每小时30次和全局每日预算；注册提交另有限流。备份恢复清除注册验证码，避免恢复旧验证码。

## Spug 短信

在 [账户设置](https://user.spug.cc/setting) 完成实名认证，在控制台开通平台官方验证码模板和充值，将模板编码填到后台“管理设置 → 短信认证 → 使用Spug”；也可继续使用服务端 `JUHE_SPUG_TEMPLATE_CODE` 环境配置。选择仅含 `code` 变量、固定“十分钟内有效”的模板，手机注册、绑定/换绑和找回密码共用这一个模板；服务端实际验证码也为10分钟有效。若原编码对应 `${number}` 模板，需要换成固定十分钟模板编码。不要将普通消息推送模板或开发者 Token 填到此处。

适配器使用 `GET https://push.spug.cc/sms/<模板编码>`，只通过URL查询参数传入 `to`、`code`，一次仅发送一个手机号。`send(phone, code)` 支持4～6位英文字母或数字验证码；现有业务仍生成6位数字，按适配器的 `validityMinutes: 10` 写入真实失效时间。绑定和找回继续分别校验验证码用途。示例与模拟调用见 [Spug调用示例](spug-sms-example.md)。

模板编码本身为调用凭据：后台保存的配置使用AES-256-GCM加密后存入 `service_settings`，密钥从服务器持久化 `data/admin-key.txt` 派生；环境模式凭据留在受限 `.env.ip`/`.env`。完整模板不会回传管理页面、写入客户端或审计，GET URL还含手机号和验证码，不记录完整请求地址或短信内容。8秒超时、不跟随重定向、不自动重试。HTTP成功且响应 `code: 200` 和有效 `request_id` 才视为提交受理；最终送达和扣费请查看 Spug 控制台。失败/无法确认的发送不会留下可用验证码。

普通升级须保留原 `admin-key.txt`。数据库备份不包含此文件；恢复到新服务器且密钥改变时，原加密短信配置将无法解密并停止短信发送，须在后台重新填写模板配置。不要把密钥或模板编码放入分发包或聊天记录。

2026-09-25 用户提供的客服回复确认其个人开发者、无自有域名、香港服务器场景可用，个人实名后短信0.05元/条、失败返还；会员不包含短信额度。实际购买以控制台为准。若启用IP白名单，应填服务器实际出口IP。同日用户已确认 r6 的真实短信送达；手机注册业务验收使用隔离账号及模拟短信。

[Spug 官方短信文档](https://push.spug.cc/guide/sms)。短信状态查询需要额外的账户开发者 Token，本版未接入轮询查询，后台也不将提交成功显示为送达成功。

## 阿里云短信

仅服务端配置以下环境变量：

|变量|用途|
|---|---|
|JUHE_SMS_PROVIDER|明确设为 aliyun（旧环境未设置也保持 Aliyun）|
|ALIBABA_CLOUD_ACCESS_KEY_ID|最小权限RAM访问密钥ID|
|ALIBABA_CLOUD_ACCESS_KEY_SECRET|访问密钥Secret|
|ALIBABA_CLOUD_SECURITY_TOKEN|可选STS临时凭证|
|JUHE_SMS_SIGN_NAME|已审核短信签名|
|JUHE_SMS_TEMPLATE_CODE|已审核验证码模板，含code变量|
|JUHE_SMS_DAILY_LIMIT|全服务每日发送尝试上限，默认100|

接口使用中国站 `https://dysmsapi.aliyuncs.com` 的 SendSms 2017-05-25，ACS3-HMAC-SHA256签名，8秒超时，不跟随重定向，不自动重试。未完整配置时返回503和“短信服务尚未配置”，不生成可用模拟验证码。

开发测试只允许通过 createService 的 `testMode: true` 与显式 `testSmsAdapter` 注入；NODE_ENV=production 时拒绝该适配器。没有可以通过环境变量或网络接口开启的固定验证码。所有自动验收结果均为隔离模拟，不代表运营商真实发送已经联调。

[SendSms官方接口](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)；[ACS3签名机制](https://help.aliyun.com/zh/sdk/product-overview/v3-request-structure-and-signature)。资质、签名及模板须实际审核通过后才能使用；还需在部署地区验证真实手机送达。

## 部署约束

JUHE_PUBLIC_ORIGIN 必须为精确HTTPS origin。生产环境需至少32字符 JUHE_PROXY_SECRET；Caddy覆盖客户端IP与代理令牌头，服务只在令牌常量时间匹配并且IP格式合法时使用代理IP，不信任任意X-Forwarded-For。服务端口不直接暴露公网。限流和短信额度计数保留在服务端，短信额度跨进程重启保留。

健康检查每分钟执行数据库写探针，读写失败返回503；不是只判断进程仍存活。恢复备份时应清除用户/管理员会话、挑战、OTP和恢复码，详见部署与恢复工具。
