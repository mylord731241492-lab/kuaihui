# 本地 AI 使用与实现

适用版本：`3.8.4-juhe.6`。

## 功能范围

本次在原客户端上修复弹窗和设置，并按原消息入口重建本地 AI 流程：

- 知识库按账号、店铺保存，支持公共知识、问答增删改、JSON / CSV 导入导出和复制。
- 商品资料由原平台采集器取得，支持会话商品采集及用户手动启动全店采集，也可手动录入商品文字。
- 文字学习调用用户配置的模型，逐项核对提取事实是否来自原文；商品资料变化会使旧学习结果失效。
- 本地文字检索结合当前店铺知识、公共知识、当前商品和订单资料，生成带来源的答复。
- 试答展示答案、来源和需要人工处理的原因；最近问答中的未解决问题可转成待编辑知识草稿。试答不会发给买家。
- 原有总开关、人机协同、敏感词、回复标识和人工接管继续参与消息处理。

这是原客户端修复与缺失模块重建。旧服务器内部提示词、旧云端知识和旧向量索引没有找回；当前检索采用本地文字分词与相关度筛选，不需要额外配置 embedding 模型。

## 配置和使用

1. 在客户端登录，打开顶部 **AI配置**。
2. 在 **模型连接** 填写自己的 API 基础地址、模型名称和密钥，选择接口格式后保存并测试连接。支持 Chat Completions 和 Responses，实际可用性取决于模型服务。基础地址示例为 `https://api.example.com/v1`，不要填写整个生成接口路径。
3. 在 **知识库** 选择店铺或公共库，录入或导入自己的问答。
4. 在 **商品学习** 选择已登录店铺，点击“从已登录店铺采集”，刷新查看原始资料及学习状态；也可手动录入商品文字并学习。
5. 在 **试答** 选择店铺，填写商品 ID 和客户问题，核对答案及来源。
6. 确认需要自动接待后，在模型连接中明确勾选店铺、启用自动接待，并保持回复总开关开启。

自动接待默认关闭，默认不勾选任何店铺。保存模型密钥不会自动开启店铺接待。API 密钥只应通过个人配置界面填写，不要写入源码、示例文件或提交到 Git。

开启商品自动学习后，采集资料会先保存到本机，学习在后台继续。模型任务最多同时执行 2 个，其中商品学习最多 1 个，问答优先。失败会保留资料和重试入口；退出造成的中断不会一直显示为“学习中”。

## 回复与发送

无可依据的业务资料、模型失败、返回格式不合法或资料引用无法核对时，流程转人工。普通问候可简短回复；配置为原文回复的精确知识命中可直接返回知识内容。

退出、切换账号、关闭 AI 或人工接管会阻止迟到回复。发送前写入本地记录，结果未知时不自动重发，避免重复发送。

拼多多使用本次请求编号、客户、正文和发送 token 核对 HTTP 成功回执。其他平台仍保留待确认状态，需要人工检查；小红书旧回执队列误匹配修复不等于已完成其事务发送确认。本轮没有向真实买家发送测试消息，不能据此宣称所有平台连续自动接待已验收。

## 本地数据与迁移

默认资料位置为 `%APPDATA%\快回\accounts\<账号范围>\`。开发隔离运行可通过 `JUHE_CLIENT_DATA_DIR` 指定独立客户端资料目录；不要把测试目录指向真实用户数据。

| 文件 | 用途 |
| --- | --- |
| `ai-knowledge.json` | 公共库及各店铺知识 |
| `ai-products.json` | 商品原始资料、学习状态和核对后的事实 |
| `ai-provider.json` | 模型连接、启用店铺及本机加密密钥 |
| `ai-runtime-history.json` | 最近问答和未解决问题 |
| `ai-delivery-journal.json` | 发送去重和确认状态 |

账号范围由账号服务地址与账号身份共同决定。更换账号服务地址会产生新的范围；先导出自己的知识，再在目标账号中导入，不要直接合并其他账号目录。换电脑需要重新填写密钥，因为 `safeStorage` 密文依赖本机系统保护。

知识和商品保存在本机；生成所需的检索结果、商品与订单片段和近期对话会发送到配置的模型服务。账号与授权仍由账号服务负责，安装包不携带个人知识或密钥。

## 尚未覆盖

- 商品学习当前处理文字。纯图片资料没有接入 OCR / 图片识别，会明确提示未完成学习。
- 全店采集依赖已登录店铺和平台接口，本轮未批量采集用户真实店铺的全部商品。
- 本地文字检索与旧向量检索的效果未做等价验证，可通过补充知识标题、内容及适用场景改善匹配。
- 本轮真实模型联调使用合成资料，成包页面测试使用本地模型模拟服务；它们均不能替代实店消息收发验收。

构建与回归测试入口见 [构建说明](../BUILD.md)。
